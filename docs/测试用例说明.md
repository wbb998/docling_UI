# Docling UI 测试用例说明

## 概述

本文档详细说明了 Docling UI 项目的测试用例结构、覆盖范围和使用方法。测试套件采用现代化的测试框架和工具，确保代码质量和系统稳定性。

## 测试框架和工具

### 核心测试框架
- **Vitest**: 现代化的单元测试框架，基于 Vite 构建
- **React Testing Library**: React 组件测试库
- **Jest DOM**: DOM 断言扩展
- **User Event**: 用户交互模拟

### 测试环境
- **jsdom**: 浏览器环境模拟
- **Coverage**: V8 覆盖率报告
- **TypeScript**: 完整的类型支持

## 测试最佳实践

### 1. 测试命名规范
```typescript
describe('ComponentName', () => {
  it('should do something when condition is met', () => {
    // 测试实现
  })
})
```

### 2. Mock 使用原则
- 只 Mock 外部依赖 (API、浏览器 API)
- 不 Mock 被测试的组件内部逻辑
- 使用真实的用户交互模拟

### 3. 断言策略
```typescript
// 优先使用语义化断言
expect(screen.getByRole('button', { name: '开始执行' })).toBeInTheDocument()

// 避免实现细节断言
expect(component.state.isLoading).toBe(true) // ❌
expect(screen.getByText('加载中...')).toBeInTheDocument() // ✅
```

### 4. 异步测试处理
```typescript
// 使用 waitFor 等待异步操作
await waitFor(() => {
  expect(screen.getByText('操作完成')).toBeInTheDocument()
})

// 设置合理的超时时间
await waitFor(() => {
  expect(mockApi).toHaveBeenCalled()
}, { timeout: 5000 })
```

## 故障排除

### 常见问题

1. **测试超时**
   ```typescript
   // 增加超时时间
   it('long running test', async () => {
     // 测试代码
   }, 15000) // 15秒超时
   ```

2. **Mock 不生效**
   ```typescript
   // 确保在 beforeEach 中清理 Mock
   beforeEach(() => {
     vi.clearAllMocks()
   })
   ```

3. **DOM 清理问题**
   ```typescript
   // 使用 cleanup 确保 DOM 清理
   afterEach(() => {
     cleanup()
   })
   ```

### 调试技巧

1. **使用 screen.debug()**
   ```typescript
   // 输出当前 DOM 结构
   screen.debug()
   
   // 输出特定元素
   screen.debug(screen.getByRole('button'))
   ```

2. **使用 logRoles**
   ```typescript
   import { logRoles } from '@testing-library/react'
   
   // 输出所有可用的 roles
   logRoles(container)
   ```

3. **测试 UI 界面**
