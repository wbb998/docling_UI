## 快速诊断

### 系统健康检查清单
在报告问题前，请先完成以下检查：

- [ ] **服务状态**：前端(5173)和后端(8000)服务是否正常运行
- [ ] **网络连接**：能否访问 http://localhost:5173 和 http://localhost:8000
- [ ] **浏览器兼容**：使用Chrome/Edge/Firefox最新版本
- [ ] **文件格式**：确认上传的文件格式受支持
- [ ] **系统资源**：CPU和内存使用率是否正常
- [ ] **控制台错误**：浏览器开发者工具是否有错误信息

### 一键诊断脚本
```powershell
# 运行系统诊断
cd scripts/win
./diagnose-system.ps1
```

## 启动问题

### 问题1：前端服务无法启动
**症状**：运行 `npm run dev` 后报错或无法访问5173端口

**可能原因**：
- 端口被占用
- Node.js版本不兼容
- 依赖包未安装或损坏

**解决方案**：
```powershell
# 1. 强制释放端口
cd apps/web/scripts
./kill-port.ps1 5173

# 2. 重新安装依赖
cd apps/web
rm -rf node_modules package-lock.json
npm install

# 3. 启动开发服务
npm run dev
```

### 问题2：后端服务无法启动
**症状**：运行后端服务时出现导入错误或端口冲突

**可能原因**：
- Python环境问题
- 依赖包缺失
- 端口8000被占用

**解决方案**：
```powershell
# 1. 检查Python环境
python --version  # 应该是3.8+

# 2. 强制释放端口
cd scripts/win
./kill-port.ps1 8000

# 3. 重新安装依赖
cd services/api-gateway/py
pip install -r requirements.txt

# 4. 启动服务
python -m uvicorn src.main:app --host 0.0.0.0 --port 8000 --reload
```

### 问题3：服务启动后无法访问
**症状**：服务显示运行但浏览器无法访问

**解决方案**：
1. **检查防火墙设置**
2. **确认端口监听**：
   ```powershell
   netstat -an | findstr :5173
   netstat -an | findstr :8000
   ```
3. **尝试其他端口**：
   ```powershell
   # 前端使用其他端口
   npm run dev -- --port 3000
   
   # 后端使用其他端口
   uvicorn src.main:app --port 8001
   ```

## 文件上传问题

### 问题1：文件上传失败
**症状**：拖拽文件后没有反应或显示错误

**诊断步骤**：
1. **检查文件大小**：单个文件建议<100MB
2. **检查文件格式**：确认格式在支持列表中
3. **检查网络连接**：确保前后端通信正常

**解决方案**：
```javascript
// 检查支持的文件格式
const supportedFormats = [
  'pdf', 'docx', 'pptx', 'html', 'md', 'txt',
  'png', 'jpg', 'jpeg', 'tiff', 'webp',
  'wav', 'mp3', 'm4a', 'csv', 'xlsx'
]
```

### 问题2：批量上传中断
**症状**：上传多个文件时部分失败

**解决方案**：
1. **减少批量大小**：一次上传不超过10个文件
2. **检查单个文件**：逐个测试失败的文件
3. **重新上传**：清空队列后重新上传

### 问题3：URL上传失败
**症状**：输入URL后无法下载文件

**常见原因**：
- URL格式错误
- 网络访问限制
- 目标服务器不可达

**解决方案**：
1. **验证URL格式**：确保是完整的HTTP/HTTPS地址
2. **测试网络访问**：在浏览器中直接访问URL
3. **检查代理设置**：如果在企业网络环境中

## 处理执行问题

### 问题1：任务执行失败
**症状**：点击"开始执行"后任务状态变为失败

**诊断步骤**：
1. **查看实时日志**：检查详细错误信息
2. **检查参数配置**：确认没有参数冲突
3. **验证文件完整性**：确保文件未损坏

**常见错误及解决方案**：

#### 错误：参数冲突
```
错误信息：extraction_schema 与 to_formats 冲突
解决方案：选择Extraction模式时，输出格式自动锁定为JSON
```

#### 错误：远程服务未启用
```
错误信息：远程图片描述需要启用远程服务
解决方案：在系统设置中启用"远程服务"开关
```

#### 错误：文件格式不支持
```
错误信息：不支持的文件格式
解决方案：检查文件扩展名，确认在支持列表中
```

### 问题2：处理速度过慢
**症状**：任务执行时间过长

**优化方案**：
1. **调整线程数**：
   ```json
   {
     "performance": {
       "max_threads": 4,  // 设为CPU核心数
       "batch_size": 10   // 减少批处理大小
     }
   }
   ```

2. **选择合适的流水线**：
   - 快速处理：STANDARD流水线
   - 高质量：VLM流水线（较慢）
   - 音频处理：ASR流水线

3. **关闭不必要功能**：
   - 图片描述生成
   - 复杂的后处理步骤

### 问题3：任务卡住不动
**症状**：进度条长时间不更新

**解决方案**：
1. **检查系统资源**：
   ```powershell
   # 查看CPU和内存使用
   Get-Process | Sort-Object CPU -Descending | Select-Object -First 10
   ```

2. **重启任务**：
   - 点击"取消"按钮
   - 等待任务完全停止
   - 点击"重置"后重新开始

3. **重启服务**：
   ```powershell
   # 重启后端服务
   cd scripts/win
   ./kill-port.ps1 8000
   cd services/api-gateway/py
   python -m uvicorn src.main:app --host 0.0.0.0 --port 8000 --reload
   ```

## 连接与网络问题

### 问题1：SSE连接错误
**症状**：显示"SSE连接错误"或"连接中断"

**说明**：这是正常现象，系统会自动切换到轮询模式

**验证轮询模式**：
1. 查看控制台日志：应显示"已切换到轮询模式"
2. 观察任务进度：应该每2秒更新一次
3. 功能正常：任务执行不受影响

### 问题2：API请求失败
**症状**：前端显示网络错误或404

**诊断步骤**：
1. **检查后端服务**：
   ```powershell
   curl http://localhost:8000/convert
   ```

2. **检查代理配置**：
   ```javascript
   // vite.config.js
   proxy: {
     '/api': {
       target: 'http://localhost:8000',
       changeOrigin: true,
       rewrite: (path) => path.replace(/^\/api/, '')
     }
   }
   ```

3. **检查CORS设置**：确保后端允许跨域请求

### 问题3：实时更新不工作
**症状**：任务进度不更新或更新延迟

**解决方案**：
1. **确认连接状态**：查看右侧面板的连接指示器
2. **手动刷新**：点击"刷新状态"按钮
3. **重新连接**：刷新页面重新建立连接

## 性能问题

### 问题1：内存使用过高
**症状**：系统响应缓慢，内存占用持续增长

**解决方案**：
1. **减少并发处理**：
   ```json
   {
     "max_threads": 2,
     "batch_size": 5
   }
   ```

2. **清理临时文件**：
   ```powershell
   # 清理临时目录
   cd storage
   rm -rf uploads/* outputs/* artifacts/*
   ```

3. **重启服务**：定期重启后端服务释放内存

### 问题2：CPU使用率过高
**症状**：系统卡顿，风扇噪音大

**优化方案**：
1. **降低线程数**：设置为CPU核心数的50%
2. **启用节能模式**：在系统设置中启用
3. **分批处理**：将大批量任务分成小批次

### 问题3：磁盘空间不足
**症状**：处理失败，提示磁盘空间不足

**解决方案**：
1. **清理存储目录**：
   ```powershell
   cd storage
   # 清理7天前的文件
   Get-ChildItem -Recurse | Where-Object {$_.LastWriteTime -lt (Get-Date).AddDays(-7)} | Remove-Item -Force
   ```

2. **配置自动清理**：
   ```json
   {
     "storage": {
       "auto_cleanup": true,
       "retention_days": 7
     }
   }
   ```

## 结果输出问题

### 问题1：下载文件为空
**症状**：下载的文件大小为0或内容为空

**可能原因**：
- 处理过程中出错
- 文件格式转换失败
- 权限问题

**解决方案**：
1. **检查处理日志**：查看是否有错误信息
2. **重新处理**：使用不同的参数重试
3. **检查原文件**：确认原文件内容正常

### 问题2：输出格式不正确
**症状**：下载的文件格式与预期不符

**解决方案**：
1. **检查输出格式设置**：确认选择了正确的格式
2. **验证处理模式**：
   - Conversion模式：支持多种格式
   - Chunking/Extraction模式：只输出JSON

### 问题3：中文内容乱码
**症状**：输出文件中的中文显示为乱码

**解决方案**：
1. **检查文件编码**：确保使用UTF-8编码
2. **浏览器设置**：设置正确的字符编码
3. **重新处理**：在系统设置中指定编码格式

## 系统错误代码

### HTTP状态码
- **200 OK**：请求成功
- **400 Bad Request**：参数错误或冲突
- **404 Not Found**：接口不存在
- **500 Internal Server Error**：服务器内部错误

### 业务错误代码
- **E001**：文件格式不支持
- **E002**：文件大小超限
- **E003**：参数配置冲突
- **E004**：远程服务未启用
- **E005**：处理超时
- **E006**：磁盘空间不足
- **E007**：内存不足
- **E008**：网络连接失败

### 错误信息中文化
系统会自动将错误信息转换为中文，包括：
- 参数验证错误
- 文件处理错误
- 网络连接错误
- 系统资源错误

## 日志分析

### 前端日志
**位置**：浏览器开发者工具 → Console

**关键信息**：
- SSE连接状态
- API请求响应
- 组件渲染错误
- 用户操作记录

### 后端日志
**位置**：后端服务控制台输出

**关键信息**：
- API请求处理
- 文件处理进度

### 日志级别
- **DEBUG**：详细调试信息
- **INFO**：一般信息记录
- **WARNING**：警告信息
- **ERROR**：错误信息
- **CRITICAL**：严重错误

1. **时间戳对比**：前后端日志时间对比
2. **请求ID追踪**：通过job_id追踪完整流程
3. **错误模式识别**：查找重复出现的错误
4. **性能分析**：分析处理时间和资源使用

## 紧急恢复

### 完全重置系统
当系统出现严重问题时，可以执行完全重置：

```powershell
# 1. 停止所有服务
cd scripts/win
./kill-port.ps1 5173
./kill-port.ps1 8000

# 2. 清理临时数据
cd storage
rm -rf uploads/* outputs/* artifacts/*

# 3. 重置前端
cd apps/web
rm -rf node_modules package-lock.json
npm install

# 4. 重置后端
cd services/api-gateway/py
pip install -r requirements.txt --force-reinstall

# 5. 重启服务
cd apps/web/scripts
./start-dev.ps1
```

### 数据备份与恢复
```powershell
# 备份重要数据
cd storage
tar -czf backup_$(Get-Date -Format "yyyyMMdd_HHmmss").tar.gz outputs/

# 恢复数据
tar -xzf backup_20250909_120000.tar.gz
```

### 配置重置
```powershell
# 重置为默认配置
cd configs
cp default/* dev/
```
