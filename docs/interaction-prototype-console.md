# Docling 控制台三栏式布局 - 详细交互原型

基于选定的方案A，本文档详细描述控制台三栏式布局的交互流程、状态变化和用户体验设计。

## 1. 整体布局结构

### 1.1 三栏布局定义
```
┌─────────────────────────────────────────────────────────────────────────────────┐
│ Header Bar (60px)                                                               │
├─────────────────────────────────────────────────────────────────────────────────┤
│ ┌──────────────┐ ┌─────────────────────────────────────────┐ ┌──────────────┐ │
│ │ Left Sidebar │ │           Main Content Area             │ │ Right Drawer │ │
│ │   (200px)    │ │            (flex-grow)                  │ │   (300px)    │ │
│ │              │ │                                         │ │  (可滑出)    │ │
│ │              │ │                                         │ │              │ │
│ │              │ │                                         │ │              │ │
│ └──────────────┘ └─────────────────────────────────────────┘ └──────────────┘ │
└─────────────────────────────────────────────────────────────────────────────────┘
```

### 1.2 响应式断点
- **Desktop (≥1200px)**: 三栏完整显示
- **Tablet (768px-1199px)**: 右侧抽屉默认收起，点击展开覆盖
- **Mobile (<768px)**: 左侧导航收起为汉堡菜单，右侧抽屉全屏覆盖

## 2. 左侧导航栏 (Left Sidebar)

### 2.1 导航结构
```
📁 文件管理
   ├─ 📤 文件上传      [当前选中]
   └─ 📋 上传队列

⚙️ 处理配置  
   ├─ 🎯 目标模式
   ├─ 🔧 流水线设置
   └─ ⚡ 附加功能

📊 任务监控
   ├─ 🚀 执行控制
   ├─ 📈 进度监控  
   └─ 📝 日志查看

📋 结果管理
   ├─ 👁️ 结果预览
   └─ 📥 下载中心

🔧 系统设置
   ├─ ⚙️ 性能调试
   └─ 🌐 远程配置
```

### 2.2 导航交互规则
- **选中状态**: 蓝色背景 + 左侧蓝色边框
- **悬停效果**: 浅灰色背景
- **点击行为**: 切换主内容区显示对应功能面板
- **状态指示**: 
  - 🔴 错误状态 (配置冲突)
  - 🟡 警告状态 (需要注意)
  - 🟢 正常状态
  - 📊 进行中 (任务执行)

### 2.3 移动端适配
- 汉堡菜单图标 (☰) 位于Header左侧
- 点击展开全屏导航覆盖层
- 选择项目后自动收起导航

### 4.2 抽屉交互规则
- **展开/收起**: 点击右上角箭头或主内容区的任务状态按钮
- **实时更新**: SSE连接实时更新进度和日志
- **滚动行为**: 日志区域自动滚动到最新内容
- **响应式**: 移动端全屏覆盖，桌面端侧边滑出

### 4.3 状态指示系统
- **🟢 正常**: 连接正常，无错误
- **🟡 警告**: 有警告信息，但可继续
- **🔴 错误**: 出现错误，需要处理
- **🔄 进行中**: 任务正在执行
- **⏸️ 暂停**: 任务已暂停
- **✅ 完成**: 任务成功完成

## 5. 关键交互流程

### 5.1 文件上传流程
1. **拖拽上传**: 文件拖入 → 显示拖拽提示 → 释放后开始上传
2. **点击上传**: 点击按钮 → 打开文件选择器 → 选择后开始上传
3. **URL输入**: 输入URL → 验证有效性 → 下载并添加到队列
4. **进度反馈**: 上传进度条 → 完成后显示✅ → 自动添加到处理队列

### 5.2 配置与校验流程
1. **模式选择**: 点击目标模式 → 其他模式自动取消 → 相关配置项显示/隐藏
2. **参数校验**: 配置改变 → 实时校验 → 显示冲突提示 → 提供解决建议
3. **高级模式**: 切换开关 → 显示更多配置项 → 保持简单模式的基础配置

### 5.3 任务执行流程
1. **开始处理**: 点击开始 → 参数最终校验 → 发送API请求 → 获取job_id
2. **进度监控**: SSE连接 → 实时接收进度更新 → 更新UI状态
3. **错误处理**: 接收错误信息 → 显示中文错误提示 → 提供重试选项
4. **完成处理**: 接收完成信号 → 更新状态 → 显示结果预览入口

## 6. 错误处理与用户反馈

### 6.1 错误类型与提示
- **网络错误**: "网络连接失败，请检查网络设置"
- **文件格式错误**: "不支持的文件格式，请选择PDF、DOCX等支持的格式"
- **参数冲突**: "当前配置存在冲突：选择分块模式时输出格式必须为JSON"
- **后端错误**: "服务器处理出错，错误代码：400，请稍后重试"

### 6.2 成功反馈
- **上传成功**: 绿色✅图标 + "文件上传成功"
- **处理完成**: 通知弹窗 + 结果预览按钮
- **配置保存**: "配置已保存" Toast提示

### 6.3 加载状态
- **骨架屏**: 初始加载时显示内容骨架
- **进度条**: 文件上传和处理进度
- **加载动画**: 按钮点击后的loading状态

## 7. 可访问性与用户体验

### 7.1 键盘导航
- **Tab键**: 按逻辑顺序在可交互元素间切换
- **Enter/Space**: 激活按钮和选择项
- **Esc键**: 关闭弹窗和抽屉
- **方向键**: 在选项组中导航

### 7.2 屏幕阅读器支持
- **语义化HTML**: 使用正确的标签和ARIA属性
- **替代文本**: 图标和图片提供alt描述
- **状态通知**: 重要状态变化通过aria-live通知

### 7.3 性能优化
- **虚拟滚动**: 大量日志条目时使用虚拟滚动
- **懒加载**: 非关键内容延迟加载
- **防抖节流**: 搜索和实时校验使用防抖
- **缓存策略**: 配置项和结果适当缓存

## 8. 开发实现要点

### 8.1 状态管理
- **Redux Toolkit**: 全局状态管理
- **RTK Query**: API调用和缓存
- **本地状态**: 组件内部状态使用useState

### 8.2 组件架构
- **容器组件**: 负责数据获取和状态管理
- **展示组件**: 纯UI展示，接收props
- **自定义Hook**: 复用逻辑抽取为Hook

### 8.3 样式方案
- **Material-UI**: 基础组件库
- **主题定制**: 符合品牌色彩的主题
- **响应式**: 使用MUI的断点系统

这个交互原型将指导后续的具体开发实现，确保用户体验的一致性和功能的完整性。
